# Sample concerns for manual inspection

These examples are intended to exercise the prototype's evidence-grounded decision-preparation path. They are not benchmark cases and do not establish effectiveness.

## Running scenario from the paper

> A public animal profile should allow a visitor to register initial interest without implementing the full adoption workflow. What architectural alternatives and validation needs should be considered?

Inspect whether the response distinguishes alternatives from accepted decisions and raises relevant concerns such as consent/privacy, duplicate submissions, staff visibility, API contracts, domain boundaries, assumptions, risks, and validation needs when supported by the corpus.

## Evidence sufficiency

> Which deployment topology is currently approved for this system?

With the provided seed corpus, this detail is not established. Inspect whether the prompt contract discourages the model from presenting unsupported information as an accepted architectural fact.

## Trade-off framing

> Should a new concern always be implemented as a separate microservice?

Inspect whether the response avoids a universal prescription and instead frames the answer in terms of evidence, alternatives, consequences, assumptions, and validation needs.
